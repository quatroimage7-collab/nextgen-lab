導入の順番
1. 公式窓口へバウチャープランの見積を依頼する。
   https://azure.kc-cloud.jp/solution/368/
   https://azure.kc-cloud.jp/contact/
2. 大学の購入手続き・メールへのAI利用承認を確認し、承認された方法で発注。
3. 提供されたAzureアカウントで初回ログイン。無料Azureアカウントを別途作る必要があるとは限らないため、提供元の案内に従う。
4. リソースグループ、Azure OpenAI、モデルのデプロイを準備。
5. Azure OpenAIの基本URL、APIキー、デプロイ名を控える。
6. Azure portalで「カスタム テンプレートのデプロイ」を開き、azuredeploy.jsonを読み込む。
7. 新しいフロー名・Azure情報・自分の所属氏名と署名を入力し、作成。
8. API接続「フロー名-outlook」を本人の大学Microsoft 365アカウントで認証。
9. 接続確認後にLogic Appを有効化。新着メールから作成された下書きを確認する。

入力時の注意
- Azure用IDと大学メール用IDは異なる場合がある。
- Azure OpenAIのURLは基本URL。/openai/v1/chat/completionsは付けない。
- デプロイ名はAzureで設定した名前。モデル名と区別する。
- 署名の改行は半角 | を入力。例：○○大学|学務課|山田 花子
- 既存フローと同名にしない。職員ごとに本人用の接続を作成する。

費用・契約
バウチャーの条件、利用可能額、初期費用、有効期限、超過時の請求・停止方法は見積と契約で確認してください。
大学共通契約を使う場合、職員一人ずつバウチャーを買う必要があるとは限りません。
APIキーやパスワード、認証済みのメール接続は職員間で共有しないでください。
Power Automate Premiumを使う構成ではありません。Azureの利用料は発生します。

データと運用
APIキー・認証トークン・元の購読ID・個人の署名・個人のAI接続先は配布設定に含めていません。
キーは配布先でsecurestringとして入力します。入力後にエクスポートした設定やパラメーターをそのまま共有しないでください。
フローの編集権限がある人から秘密情報を完全に隠す仕組みではありません。

対象は、添付なし・差出人アドレスにreplyを含まない通常の新着メールです。特別な件名は不要です。
条件通過後に件名・差出人・本文をAzure OpenAIへ送り、reply/skip/reviewを判断します。
返信不要な通知等はAI判断で除外します。誤判定の可能性があるため、受信トレイも確認してください。
カレンダー連携、自動送信はありません。送信前に本人が確認します。
Outlookの登録済み署名は取得しません。設定した署名を本文に追加します。
永続的な重複防止、AI送信前の機密・保護メールの自動除外は未実装です。
機密性のAI判定はAIへ送った後なので、送信前の除外にはなりません。
実行履歴のResubmitを繰り返すと下書きが重複する可能性があります。

差出人名の取得
GetSenderは受信メールのfrom.emailAddress.nameを取得します。連絡先帳の検索や外部サービスでの個人特定は行いません。表示名は送信者が設定できるため本人確認の根拠ではありません。

重要：この第3版のテンプレートは新規作成用です。既存のnextへそのまま上書きしないでください。
添付された個人用エクスポートは配布ZIPに含めていません。署名はOutlookの設定からではなく導入時のSignature Linesから挿入します。
